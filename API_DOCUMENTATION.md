# Knots Platform API Documentation (Member 2 Modules)

Welcome to the API Reference for **Member 2** modules: **Profiles**, **Jobs & Internships**, and **Platform Analytics**.
Interactive OpenAPI/Swagger documentation is automatically generated by FastAPI and can be accessed when running the backend server locally or in staging:

- **Swagger UI (Interactive API Explorer)**: `http://localhost:8000/docs`
- **ReDoc (Specification Reference)**: `http://localhost:8000/redoc`
- **OpenAPI JSON Schema**: `http://localhost:8000/openapi.json`

---

## 1. Profiles API (`/api/v1/profiles`)

The Profiles API manages user profiles, educational history, employment experience, profile picture uploads, and peer skill endorsements.

### Endpoints Overview

| Method | Endpoint | Description | Auth Required |
|---|---|---|---|
| `GET` | `/api/v1/profiles/me` | Retrieve currently authenticated user's profile (auto-initializes if missing) | Yes |
| `PUT` | `/api/v1/profiles/me` | Update current user's profile (name, bio, department, grad year, skills) | Yes |
| `POST` | `/api/v1/profiles/me/picture` | Upload profile picture (`multipart/form-data`) | Yes |
| `GET` | `/api/v1/profiles/{user_id}` | Retrieve profile of any user by ID | Yes |
| `POST` | `/api/v1/profiles/me/education` | Add education record to current user's profile | Yes |
| `PUT` | `/api/v1/profiles/me/education/{id}` | Update education record by ID | Yes |
| `DELETE` | `/api/v1/profiles/me/education/{id}` | Delete education record by ID | Yes |
| `POST` | `/api/v1/profiles/me/experience` | Add employment/experience record to current user's profile | Yes |
| `PUT` | `/api/v1/profiles/me/experience/{id}` | Update experience record by ID | Yes |
| `DELETE` | `/api/v1/profiles/me/experience/{id}` | Delete experience record by ID | Yes |
| `POST` | `/api/v1/profiles/{user_id}/skills/{skill_name}/endorse` | Endorse a skill on a peer's profile | Yes |
| `DELETE` | `/api/v1/profiles/{user_id}/skills/{skill_name}/endorse` | Remove skill endorsement from a peer's profile | Yes |

### Key Schemas
- **`ProfileResponse`**: Includes `user_id`, `first_name`, `last_name`, `bio`, `department`, `graduation_year`, `skills`, `profile_picture`, `connection_count`, and list of `endorsements`.
- **`EducationCreate`**: `institution_name`, `degree`, `field_of_study`, `start_date`, `end_date`, `gpa`, `description`.
- **`EmploymentHistoryCreate`**: `company_name`, `title`, `location`, `start_date`, `end_date`, `description`.

## 2. Jobs & Internships API (`/api/v1/jobs`)

The Jobs API manages job postings, company directories, student job applications, and employee referral requests.

### Endpoints Overview

| Method | Endpoint | Description | Auth Required |
|---|---|---|---|
| `POST` | `/api/v1/jobs/companies` | Create a new company profile | Yes (Admin/Recruiter) |
| `GET` | `/api/v1/jobs/companies` | List all companies with pagination | No (Public/Student) |
| `GET` | `/api/v1/jobs/companies/{id}` | Retrieve company details by ID | No |
| `POST` | `/api/v1/jobs/postings` | Create a new job or internship posting | Yes |
| `GET` | `/api/v1/jobs/postings` | Search & filter job postings (`job_type`, `location`, `is_remote`) | No |
| `GET` | `/api/v1/jobs/postings/{id}` | Get detailed view of a job posting | No |
| `PUT` | `/api/v1/jobs/postings/{id}` | Update job posting details | Yes (Owner/Admin) |
| `DELETE` | `/api/v1/jobs/postings/{id}` | Remove a job posting | Yes (Owner/Admin) |
| `POST` | `/api/v1/jobs/postings/{id}/apply` | Submit job application (`cover_letter`, `resume_url`) | Yes |
| `GET` | `/api/v1/jobs/applications/me` | List current user's submitted job applications | Yes |
| `GET` | `/api/v1/jobs/postings/{id}/applications` | View all applicants for a job posting | Yes (Owner/Admin) |
| `PUT` | `/api/v1/jobs/applications/{id}/status` | Update applicant status (`PENDING`, `REVIEWING`, `INTERVIEWING`, etc.) | Yes (Owner/Admin) |
| `POST` | `/api/v1/jobs/referrals` | Submit a job referral recommendation | Yes |
| `GET` | `/api/v1/jobs/referrals/me` | List referrals submitted by current user | Yes |

## 3. Platform Analytics API (`/api/v1/analytics`)

The Analytics API delivers real-time engagement insights, profile view histories, post performance metrics, and trending algorithm results.

### Endpoints Overview

| Method | Endpoint | Description | Auth Required |
|---|---|---|---|
| `GET` | `/api/v1/analytics/stats` | System-wide summary (`total_users`, `active_jobs`, `total_posts`, etc.) | No |
| `GET` | `/api/v1/analytics/platform/engagement-summary` | Platform-wide engagement rates, views, and interaction totals | No |
| `GET` | `/api/v1/analytics/profile/views?days=7` | Time-series profile view analytics for currently logged-in user | Yes |
| `GET` | `/api/v1/analytics/posts/engagement` | Aggregate post views, likes, and comment metrics for current user | Yes |
| `GET` | `/api/v1/analytics/trending-posts?limit=5&days=7` | Top trending posts weighted by views, likes, and recent activity | No |
| `POST` | `/api/v1/analytics/posts/{id}/view` | Record an analytical view event on a post | No (Optional Auth) |
| `POST` | `/api/v1/analytics/profile/{id}/view` | Record an analytical view event on a profile | No (Optional Auth) |

## Error Handling & Response Standards

All API endpoints wrap payloads in a standardized `APIResponse` envelope:

```json
{
  "success": true,
  "message": "Operation completed successfully",
  "data": { ... },
  "errors": null
}
```

When an error occurs (e.g. `400 Bad Request`, `401 Unauthorized`, `404 Not Found`), the response structure is:

```json
{
  "success": false,
  "message": "Descriptive error summary",
  "data": null,
  "errors": [
    "Detail error message 1"
  ]
}
```
